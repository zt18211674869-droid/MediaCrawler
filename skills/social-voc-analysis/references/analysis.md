# 观点提取、聚类与交叉分析

## 从研究问题选择分析视角

承接 research-brief.md 中已明确的问题、证据需求和完成标准，按 [module-framework.md](module-framework.md) 选模块、定义指标。先检查材料能支持到哪一层：产品介绍可解释定位，具体自述可揭示体验，当前功能与价格需有日期的一手来源，取得方式限用户已有材料或 guaikei MCP；缺失时保持未知。公开自述仍是作者的描述，不等于已观察或实测行为。

分析的基本单元是有上下文的具体观点：**评价对象 + 方面 + 判断 + 条件或理由**。同帖夸界面、抱怨收费、咨询安卓端，应分别提取；不要给整帖一个正负标签后丢掉矛盾。

## 来源判断与观点提取

先按 [coverage.md](coverage.md) 建立独立输入分母和分批工作清单。分析范围是本轮全部选定材料；默认不以抽查替代全量。每批返回逐来源处理与观点，完成后再汇总主题；正文精选案例不改变分析范围。

先逐来源记录纳入、排除、待核或未处理，保存理由、判定者类型与编码版本。模型自检仍标为模型判断；未处理不能写成排除。已确认的推广材料可以支持供给定位，但不能充当独立用户满意度。

再从纳入材料提取与问题相关的观点，保留连续原声、必要上下文和来源ID。只有背景或无明确观点的材料可不生成观点，写明原因；不为凑行数切碎表达。

| 分析轴 | 判定内容 |
|---|---|
| 对象与方面 | 评价哪款产品、哪项任务或属性；同名未核就保留原帖称呼和身份限制 |
| 正负向 | positive / negative / neutral / mixed；优先将可分离的正反判断拆开，不能拆时保留 mixed |
| 观点类别 | 使用自述、求助、推荐、教程、产品声明、期待、问题或背景；疑问不自动是负面 |
| 证据用途 | experience / supply / context；自称使用但属产品方宣传时如实标明，不能靠正负词改变资格 |
| 场景 | 在什么处境、由谁、为了什么任务，设备/阶段/约束是否明确 |
| 旅程阶段 | 观点发生在任务的哪个环节；材料不明则未知，不强配完整生命周期 |
| 行为与结果 | 作者实际描述怎样操作、绕行、继续、放弃以及后果；与愿望和预期分开 |
| 预期与限制 | 作者期待什么，哪些是研究者推断，版本/理解/上下文还缺什么 |

性别、年龄、付费身份、熟练度等没有依据就留未知。情绪强度可按问题需要另记，不能用感叹号推断人格。字段是一组观察视角，不要求每个来源都有完整旅程、行为和心理解释。

特别核对评价对象和语气：抱怨旧工具后自制新工具，负向观点仍归被评价的旧方案；“希望方便”“以后能查回”是期待，继续使用是一种行为，都不能自动编码为正向体验。同一作者对不同方面的正反评价分别保留，不能只抽取符合结论的一面。

需要保留一源多观点及分类联动时，使用 [opinion-contract.md](opinion-contract.md) 的独立 opinions.json，关联原 analysis.json；不要为增加观点覆盖而篡改来源原文或历史快照。

## 先归纳表达，再解释机制

1. 阅读覆盖不同查询、产品、正反表达及来源性质的小批材料，提取初始观点与描述性代码。
2. 以语义和任务相关性聚合同义或近义观点，写清类别定义、纳入/排除边界及易混淆反例。相同关键词不一定同一观点。
3. 检查大簇是否混入不同原因、少数观点是否被吞并；允许拆分、合并及保留异例，并记录规则变化。
4. 用后续材料检验、修订分类，必要时回看先前批次。关键词辅助定位和复查，不代替逐条判断。
5. 再结合场景、行为与反例提出机制解释。描述簇“重复填写时间”可以成立；升级为“认知模型不一致”则需要额外推理依据。

同一观点可以关联多个明确主题，但统计多选须披露；主题、场景和旅程是不同分类轴。不要把“录入麻烦”“多人交接”“餐后”放进同一组互斥主题。

试编码、歧义处理、规则冻结、变更影响和回编码按 [运行规范](run-workflow.md) 留痕；工具计算位置和哈希，实际阅读者负责语义判断，不自动签发完成。

## 跨维度解释差异

在相同任务与阶段下比较产品，检查正向价值和负向障碍分别在什么条件成立。产品样本量不均、版本不同或材料性质不同，应并列说明，不能按抱怨条数直接排体验优劣。

场景解释“谁在何种处境做什么”；旅程按 [journey-method.md](journey-method.md) 汇总阶段、行为、关注点、触点、障碍、补救、情绪和度量。可综合多个来源形成待验证的旅程模型，必须注明是综合，不能拼成一个人的真实经历。未覆盖阶段留白；已观测证据指标与待验证业务指标分列。

用户心理模型沿“预期规则—实际经历—落差—应对—解释与边界”推导。只有评价词、没有预期或行为时，保留线索。深入综合见 [decision-synthesis.md](decision-synthesis.md)。

## 关键词与原声

提词、领域词典、语义归并、否定保护与统计方法见 [keyword-method.md](keyword-method.md)。保留原词与归并表达的区别，默认按合格亲历自述的独立来源DF生成正负词表；宣传等材料另列。点击词可到全部归并成员的观点与原文。报告如实说明实际执行方法，词云不能代替主题解释。

每条主要发现就地展示有解释力的原声，正反经验各按需要引用。引语只证明该表达存在，发现是研究者归纳；不能用多个相似引语制造独立验证。

## 统计与排序

区分搜索返回、唯一候选、取回详情、来源单元、观点、独立作品及可辨认账号。一源多观点、一帖多评论、同作者多帖都不等于更多独立用户；保留作品与账号层的去重口径。

比例说明分子、分母、单位、窗口、材料性质和多选规则。各平台、产品或时期采样不相同时，不将样本差异解释为市场占比或需求强弱。小规模或选择性样本以条数为主，需要分布时同时提供有边界的 `n/N` 与比例，不用“非总体抽样”省略用户已要求的样本统计。

样本分布任务按 [quantitative-analysis.md](quantitative-analysis.md) 建立分类轴、合格范围和逐条归属，冻结后聚合。场景自由文本先归并为有边界的代码表；使用任务、关系与地理条件不混作互斥人群。产品、正文/评论及材料性质按问题拆分，未知和零命中保留明确去向。每项必需统计都要完成、展示并复算，不能用覆盖账齐全或代表引文数量代替。

排序结合与主问题的关系、后果、证据直接性、独立来源及反例，不固定为频率乘影响公式。高后果单例可以值得调查，但不能写成普遍现象；未评估实现成本就不填低成本。用户要求评分时披露权重、缺失与敏感性。

最终核对来源状态、观点归属、主题覆盖与未解矛盾。达到样本数或填满分类，不代表研究已回答用户的问题。

交付前回到全部原文完成观点遗漏复核，保存 coverage.md 定义的 review-ledger.json。逐条 ID 齐全、通用理由或原文复制均不能单独证明语义提取完成；缺少复核记录就如实标明尚未验证完整性。
