# 全量处理与遗漏检查

本规范处理“已取得的材料是否完整进入分析”，不保证搜尽平台内容，也不保证模型理解绝无遗漏。默认逐条处理本轮已取得、选定的全部材料；只展示精选例子不减少分析范围。需要抽样分析时，先沿用用户已授权的抽样范围；没有授权，不因上下文长度、报告篇幅或时间把全量任务缩成抽样。

## 三个不同的完成条件

| 层次 | 可以核对什么 | 不能据此声称什么 |
|---|---|---|
| 原始输入对账 | 从保存的原始返回或用户文件独立枚举记录，每条都有去向 | 平台全部内容都已采集 |
| 逐条处理覆盖 | 每条选定材料均有原文、判定和具体处理结果，零观点也有理由 | 每项语义判断都正确 |
| 观点遗漏复核 | 回到全部原文，检查遗漏的方面、条件、正反态度及少数意见 | 可数学证明观点遗漏率为零 |

“100 条都分析了”应指 100 条都有可回查的处理结果，不要求 100 条都纳入结论。排除、仅作背景、缺上下文和没有相关观点均可成立，但必须给出与该条内容有关的理由。待处理与读后仍待核分别计数，不把二者合并；不强行给歧义短句补观点以凑完成率。

## 先从原始输入建立分母

从原始文件枚举记录，保留原始文件哈希、记录位置、来源身份和文本是否可用；不要用已经筛过的 evidence 或 opinions 反推输入总数。搜索、详情、评论、回复分别列出。每个原始出现记录只能对应一种去向：进入选定材料、同一来源重复、由更完整快照替代、缺正文、解析失败或明确在本轮范围外。重复与替代项必须指向保留项；同作者相同文案不自动当成同一条来源。

校验输入集合与各去向集合的差集、交集及未知 ID，不能只看总数相等。删除一条又重复另一条时总数不变，ID 对账仍应报错。空白文本和接口失败另列，不当作已阅读，也不能无记录消失。文字、图片、视频及其转写的取得状态分别说明。

归一化 items.jsonl 之后，还要核对 items → evidence → 判定 → 观点 → 主题的连接。多个原文片段不增加独立来源数；仅选了原文中的引语片段，不等于处理了完整原文。原始字段枚举由本次实际采集映射负责；validate_coverage.py 不猜测平台返回结构，不能替代这一步。

## 分批读取，全量汇总

先用 `python scripts/prepare_coverage_review.py <run-dir>` 生成复核工作包。该工具保存输入哈希，按文字量分批，并生成全部为 pending 的 review-ledger.json；不自动判断已读，不覆盖已有账本。每批包含明确的来源 ID、完整证据文字、现有判定和观点。超长单条单独处理；如需分段，保留连续字符位置和理解所需上下文，不能只看开头或摘要。

模型或实际审阅者逐批读取原文，再保存处理结果。并行处理时各批 ID 边界固定，合并时检查遗漏、重叠和规则版本；让子任务返回逐来源结果，不只返回一段批次总结。分类规则变更后回看已处理批次，避免前后口径不同。恢复任务时依照持久账本继续，不能靠聊天上下文记忆完成情况。

首次分析在完整范围内提取所有与研究问题相关的观点。再次复核直接回看原文，不只阅读第一次摘要；特别检查一个来源中并存的正负判断、不同对象、多方面诉求、转折和条件。零观点、排除、待核和长文本需要具体复核。抽查可估计质量，不能声称已经逐条复核；只有在确实读取了全部批次后才能记录全量复核。

## 复核账本

独立观点层用于严格的全量观点验收。review-ledger.json 保存 schema_version=coverage-review-v1、source_items_sha256、source_analysis_sha256、source_opinions_sha256、review_method 和 reviews。哈希取实际文件字节；没有 opinions 时对应哈希为 null，尚不满足严格观点验收。

每条 review 对应唯一 evidence_id，含 text_sha256（原文字符串以 UTF-8 编码）、review_status（pending/complete）、assessor（model/human/mixed）和 segments。只有真实读过、完成复核才设 complete；模型自检仍为 model。

segments 使用 Python Unicode 字符索引的半开区间 [start,end)，覆盖该条全部文字，不重叠、不留空白。每段记录 outcome、opinion_ids 和 reason：

- opinion：有相关观点，关联属于该来源的真实观点 ID。观点引文必须位于该段；可以一段对应多个观点，不能靠“一段一个主题”压掉其它方面。
- background：提供背景或事实转述，说明在本次问题中的用途和为何不提取评价观点。
- irrelevant：与问题无关或无需作为观点，结合具体文字说明理由。
- uncertain：已读，但对象、含义或上下文无法确定，说明欠缺什么。

非 opinion 段不关联观点。纯标点、话题标签可以与相邻语义段一起处理，不要求机械按句切分；不能把整篇标为“已处理”来代替观点复核，也不能把全文复制到 statement 当作提取完成的证据。段覆盖是防漏工具，段内是否仍遗漏观点由语义复核判断。

初步分类账与复核账是不同产物。不能把旧 annotations 自动转换成 complete，不以关键词命中、脚本遍历、API 成功或通用模板理由充当已读证明。复核如改变资格或观点，建立保留旧版的新分析快照，重算统计并同步报告；不能仅修复账本外观。

## 交付前验收

运行 `python scripts/validate_coverage.py <run-dir> --output <run-dir>/coverage-validation.json`。需要声明本轮全部处理并完成确定性编码时，加 `--require-complete`；不满足则返回非零状态。原有 validate_analysis.py、validate_opinions.py 继续检查原文、引用及分类连接。

分别报告原始返回数、去重/替代数、缺文字数、选定材料数、已记录处理数、未处理数、待核数、纳入数、排除数、无观点材料数及实际提取观点的来源数。每个覆盖率必须注明分母；“185/185 有分类记录”不能写成“观点完整率 100%”。正文只举例，不用引文出现次数代替分析覆盖。

无待处理且每条都有完整复核记录，可以说明逐条复核已完成；仍有 uncertain 时同时披露待核数量，不能写成所有观点都已确定。旧包没有复核记录时应写“原文与处理记录已对账，尚不足以验证观点提取完整性”，不能倒填一份历史上的完成证明。数据链路通过、模型全量复核和人工复核分别说明，不能把模型或子代理的检查称为真人独立审阅。

校验失败时修正遗漏或交付明确标注覆盖范围的阶段性报告。未处理、上下文不足或无法解析的内容不静默删除；重要少数意见不因频次低而省略。最终报告可以简洁，完整原文、逐条处理和复核结果留在附件中供追查。
