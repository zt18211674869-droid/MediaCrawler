# 从观点到有依据的解释

本文件用于观点聚类后的综合。深度以研究问题为准：了解竞品需要解释优势为何成立、评价为何分化；提出MVP、界面或优先开发方案只在用户需要时展开。

## 回到问题与共同维度

将主要发现关联 research-spec 的问题 ID。竞品先形成“对象 × 共同任务/维度”的比较，每格说明表现、证据性质、适用条件和未知。不能把一家的产品宣传与另一家的具体抱怨直接排名；同名应用、原型和合集不合成一个产品。

合并与拆分看实际问题、成立条件及判断方向，不能只按来源相同或关键词重合。同一任务中的共同困难可综合，不同原因、影响或处理方向保留差异；原因未知时不假定机制一致。例如同为“简洁”，仍需区分入口短、录入少、汇总清楚或功能少。分类标签不能代替洞察，合并后保留个案证据。

## 每项发现的推理链

| 环节 | 要回答什么 |
|---|---|
| 观察 | 哪些来源具体说了什么、做了什么；正向与负向分别是什么 |
| 情境 | 在何种任务、阶段和约束下发生，原有办法是什么 |
| 解释 | 这些表达可能说明什么，哪些属于研究者推断，有无其他解释 |
| 条件与反例 | 什么条件下有效或失效，是否存在相反体验，关键变量是否缺失 |
| 对主问题的意义 | 怎样改变对定位、优势、不足、选择或需求的理解 |

支持、反证与限制跟随发现保存。没有找到反例不等于无反例；同帖评论、同作者多帖或转载可能相关，分开保留去重来源数与可辨认账号数，不视作相互独立的验证。未实际观察的自述行为不能标成实测结果。

综合时核对状态与时点：功能评价不能改写成实际使用；期待或意向不能改写成已发生的行为；设计假设不能放进已发现的障碍。历史材料可以解释场景和替代路径，但其性能与限制只代表当时的自述，不能因本次采集日期较新就写成当前产品表现。建议据此提出时，说明哪些问题仍需在当前条件下验证。

这些是内部分析关系，成稿时按 [report-language.md](report-language.md) 转为具体、客观的专业表述。“存在质疑”的主张不会因“有人支持品牌”而被推翻，后者通常属于其他观点；不能为了填满反证字段而把不同立场当作事实反证。机制解释若缺直接证据，应提出有条件的解释或只报告已观察表达，避免用抽象术语掩盖推理缺口。

“决定留存”“协作比功能丰富更重要”等因果或优先关系需要相应比较依据。仅见到交接困难，应限定为该任务中的障碍；不能从一次抱怨推断流失率。

## 场景与旅程综合

按材料建立任务阶段和分支，展示各阶段的目标、动作、产品触点、正反体验、补救与结果。阶段名称可因任务改变，不机械套“认知—购买—留存”。

每个阶段回链相关观点。多来源拼成的地图注明“跨来源综合”；真实个案路径另行标识。地图缺失阶段、转折或结果时，明确未知，不用箭头暗示已经观察到完整因果链。

跨产品比较保持任务条件相近；一家的查询体验不能直接与另一家的记录效率比输赢。

## 用户心理模型

用证据建立用户如何理解产品、预测结果和作出取舍的解释：

**预期规则 → 实际经历 → 落差或符合预期 → 应对行为 → 研究者解释及适用边界。**

例如作者按“一餐”理解记录，而描述多食材拆分造成餐次不符，可以提出记录单位不一致的线索；若作者也承认可能没找到功能，应同时保留可发现性、版本或使用方式等替代解释。示例只能说明推理结构，不能直接作为新研究发现。

心理模型回链实际观点与来源，区分用户明说、行为线索和研究者推断。不同家庭的取舍可能相反；按任务和行为分组，不编造人格画像或人口属性。一条线索不升级为普遍心理规律，多个视图复用同一证据不增加确定性。

没有足够材料时，可列“已观察的判断线索及待核部分”，不为空间填心理标签。

## 需要设计建议时再向行动展开

用户要改善产品或定义新产品时，先说明谁在什么任务中遇到什么问题、预期改善什么，再提出方向与验证办法。已知问题和待核原因分开，不能仅因都可“增加提示”而合并。实现方式是重点时再展开界面或技术动作。

每条建议是可推翻的假设，应对应支持发现、观察指标和失败条件。现有能力、团队职责与成本只依据已知资料判断，未知就保留未知；核对遵守本 Skill 的外部调用边界。不把已具备的能力包装为新增方向，不因高频自动排首版。

证据只支持案例参考时可以没有建议，保留待核问题；参考案例和正向评价不能自动证明某项能力值得建设或已产生效果。了解竞品可停在解释清楚的差异、条件与缺口。

## 综合验收

综合发现时，按主张将定量与质性材料连接起来：分布说明某种表达出现的范围及差异，场景与连续原声解释条件和理由，真实路径解释作者如何应对。不同来源承担的作用应明确；频率不能单独证明动机，单个完整案例也不能证明普遍性。没有足够数量时保留案例层解释，没有过程证据时不补造行为链。

具体信息先说清该来源的核心观点，再提供案例；综合发现提炼共同问题及影响，建议说明拟改善什么。这些层次各有分工，不以增加抽象词表示洞察升级。按 [output.md](output.md) 安排展示，不把全部分类升级为核心洞察，也不逐个复述数字。

主要结论应能回答：谁在何种条件下觉得哪里有效或受阻；为何形成差异；支持和反例是什么；哪些未知会改变判断。检查有没有把共同主题当产品差异、把归纳加引号冒充原声、把推广当独立体验。

不要靠完整表格、更多分类或脚本通过代替这一步。存在决定性缺口时，在授权范围内补证，或收窄结论并说明尚不能回答的部分。
