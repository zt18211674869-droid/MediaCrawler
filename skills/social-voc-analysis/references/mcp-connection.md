# guaikei MCP 前置检查

本 Skill 唯一外部调用是已安装的 guaikei（怪客）MCP；不连接其他服务，也不绕过 MCP 直接调用 API/CLI。本文件检查现有连接，不提供安装、登录或密钥收集流程。用户明确只要求离线分析时跳过在线检查；在线研究明确业务目的后，取数前做本检查。关键意图待确认时可发现工具，但不以付费业务调用试探用户想研究什么。

## 发现与确认

1. 从当前宿主连接状态和工具发现能力中寻找 guaikei/怪客服务。依据服务来源和工具描述确认身份，不猜工具名、服务器地址或工具前缀。
2. 读取本轮平台和操作的真实 input schema、用途、返回说明与状态约定。只核对需要的能力；一个平台成功不代表全部平台可用。
3. 宿主若提供连接诊断，或服务有明确不创建任务、不计费的健康检查，可使用一次。仅列表可见时记录 tools_visible，鉴权与业务仍记未验证。
4. 没有无成本检查工具时，不另发测试搜索。用本轮已授权、参数与预算明确的首个必要业务任务同时确认可用性，复用结果并计入预算。仅要求检查连接而未授权取数时，报告能查到的状态和业务未验证，不为测通发起采集。

## 处理检查结果

| 观察到的情况 | 执行方式 |
|---|---|
| 未发现工具、连接断开或失败 | 提示联系仓库维护者或 MCP 服务提供方，停止依赖该服务的取数 |
| 鉴权失效、共享额度或余额不足 | 提示联系仓库维护者或 MCP 服务提供方，停止依赖该凭据/额度的后续调用；不索取 Key |
| 所需操作缺失、平台权限或套餐不支持目标 | 说明具体限制并提示联系仓库维护者或 MCP 服务提供方，不反复探测或悄悄降低目标后称完成 |
| 网络或限流暂时失败 | 仅在未创建任务、无重复收费风险且预算允许时按服务要求最多重试一次；仍失败提示联系仓库维护者或 MCP 服务提供方 |
| 提交结果不明或已受理但超时 | 记录未完成状态，避免再创建；仅用明确支持的同任务查询。达到截止时间后提示联系仓库维护者或 MCP 服务提供方 |
| 合法空结果 | 本次业务调用成功；如实记录零条，按研究需求和预算决定后续，不当成连接失败 |
| 任务受理/处理中 | 通信正常，数据尚未就绪；按约定查询，不开始基于该任务的分析 |
| 有效数据 | 核对字段与原文映射，保存原件后进入分析 |
| 未知返回结构 | 保存原件，标记映射未确认；无法从实际 schema 确认时提示联系仓库维护者或 MCP 服务提供方协助核对版本，不猜字段 |

单个平台不可用不等于整个 MCP 断开；其他已授权且有效的材料可以继续处理并披露缺口。没有有效数据时停在数据准备阶段。已有历史材料可做有限分析，不能写成实时取数完成。

故障提示示例：

> 怪客（guaikei）MCP 当前无法完成小红书评论采集，原因是〔观察到的连接错误/权限错误/数量限制〕。请联系仓库维护者或 MCP 服务提供方协助处理。本轮已保留取得的数据，受影响的采集尚未完成。

只提示用户联系，不自动代发消息；不虚构仓库维护者或 MCP 服务提供方的电话、邮箱或链接。提供时间、平台、操作、实际错误码及脱敏说明，不复制 token、鉴权头、带密钥 URL 或完整敏感日志。

## 检查记录

在 research-spec 或 manifest 的 mcp_check 中记录 checked_at、实际服务标识、所需工具、schema 来源/版本（可得时）、transport_status、auth_status、capabilities、验证方法、失败原因和 affected_operations。未知状态写 unknown，不用 installed 替代 connected，不用 connected 替代业务成功。复用本轮仍有效的检查，断连或业务报错时更新，不每次调用重复预检。
