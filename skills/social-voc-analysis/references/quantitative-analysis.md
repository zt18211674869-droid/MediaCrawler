# 样本分布与定量交付验收

用于需要回答“出现多少、占比怎样、哪些更集中、不同对象有何分布差异”的研究。沿用 research-spec 的主问题，不把每份案例探索强制改成统计报告。

## 先确定本轮回答层次

- `case_exploration`：解释具体案例、机制或待验证线索。可以只用条数与案例，不把引文数量称为总体分布。
- `sample_distribution`：用户要求频次、占比、主导观点或场景，或本轮选用模块需要分布比较时采用。采集/编码前明确“问题 → 必需统计表 → 合格分母 → 分类轴 → 完成标准”。不能仅交代表案例；无法计算的项目保留为未完成或未知，并说明实际缺口。

在 research-spec 中保存模式、理由及定量计划。规模小、非随机选样不会自动禁止样本内比例；需要明确资格、`n/N` 和适用范围，以数量为主并避免过细精度。样本比例不外推为用户总体、市场份额、真实使用频率或业务转化率。

## 使用场景的正文要求

报告分析使用场景时，在正文的场景模块直接提供数量汇总或分布，至少交代有效样本数、各场景数量及分母、必要占比、来源去重方式、多选规则和未说明场景数量。正文可采用一张简洁表或图，详细成员继续在完整统计中核查。关系类型、地域条件或功能提及率不能代替实际使用任务分布。

案例探索也应说明场景例证条数与范围；材料不能支持分布时，明确统计缺口，不用少量案例编造总体比例。审阅时直接检查正文是否具备场景统计；只有场景描述、原声或附件链接，不能视为场景模块交付完整。

## 从逐条材料到统计

1. **固定输入与合格分母。** 对账召回、取得、非空、选定、纳入、排除和待核数量；保存逐条具体理由。讨论材料、使用自述、宣传与求助的资格按问题分别定义，不把全部评论直接作为所有指标的分母。各分母从全部符合该指标资格的来源独立建立，不能从已有观点或精选证据反推；只有使用事实、没有评价观点的来源，也可能属于实际使用统计的分母。
2. **建立可汇总代码表。** 每个统计轴有类别定义、纳入/排除边界、同义归并、未知处理及多选规则。使用任务、关系、地理条件、动机、功能和态度分开编码；不能把重叠维度拼成互斥人群。自由文本 scene 需归并后才能汇总。
3. **全量编码选定材料。** 一源多观点分别提取，仍按声明单位去重。产品级实际使用、意向和未知分别记录；不将替代产品的经历计入目标产品分母。正文与评论、来源性质、必要时间窗和产品分别统计或明确合并依据。
4. **冻结后聚合。** 统计从同一分析、观点及分类快照计算，保存分子/分母成员、单位、窗口、多标签和缺失规则。未知、无场景和没有明确评价单列；不自动当中性、零或从分母消失。多标签覆盖不可加总，互斥构成须完整分配。
5. **交付并复算。** 关键统计显示数量、必要比例和分母口径，支持回查原文；结合讨论页覆盖与来源集中度解释数量，不将频率直接等同重要性。全部必需表在明确的完整统计页或附件入口提供，主报告按发现选择必要指标，不要求把每项统计都放入正文。所需表未生成、无法取得或未复算时，不能将定量研究标为完成。

## 可复算文件契约

以下文件补充现有 analysis/opinions/coverage 合同，不替换原文、观点或全量复核账。已有等价数据结构可映射后核验；脚本只检查结构与算术，分类含义、分母选择及报告展示仍需语义与成稿审阅。

### quantitative-spec.json

主计划 research-spec 是问题和必需统计的权威来源；本文件的 spec 作为其执行计划，问题 ID、模式与必需表不得漂移。

`schema_version: quantitative-spec-v1`；`mode` 为上述两种模式。`questions` 含真实问题 `id`；`required_tables` 每项保存 `id/axis_id/question_ids`。分布研究至少有一张明确的必需表，表数与类别按任务决定。案例探索可留空，不借模式选择规避用户已要求的定量工作。

### quantitative-coding.json

`schema_version: quantitative-coding-v1`；`source_analysis_sha256/source_opinions_sha256` 绑定当前 analysis.json 和 opinions.json 的实际字节。

`axes` 每项保存 `id/title/unit/multi_label/scope_ids/categories/unknown_category_id/eligibility/window`。`unit` 为 `source` 或 `opinion`；scope_ids 分别引用 analysis.evidence.id 或 opinions.opinions.id，全部来自纳入材料。source 轴内，同一平台、作品与来源单元身份不能重复，多个片段先合并为同一来源代表，不能增加分母。

`categories` 各项含稳定 `id/label`，详细语义边界在本轮 coding_rules/代码表中保存。`assignments` 每项为 `axis_id/entity_id/category_ids`，每轴每个范围内实体恰一条，零命中也保留空分类记录。轴声明 unknown_category_id 时，不能空归属，未知不能与实质类别并存。`multi_label:false` 要求每个实体恰属一类；多选轴允许重叠。确实无匹配的覆盖轴可保留空 category_ids，不自动加“未知”改变含义。

### quantitative-facts.json

`schema_version: quantitative-facts-v1`；`source_coding_sha256` 绑定上述分类文件。`tables` 每项保存 `id/axis_id/unit/multi_label/rows`，必需表必须存在。各类别都保留一行，包括零命中；每行含 `category_id/label/numerator_ids/denominator_ids/n/N/percent`，可另有 `discussion_pages`。

分母等于该轴 scope_ids；分子等于该类别全部冻结成员，不能仅选代表引文。n/N 依声明单位计算；百分比按 100×n/N 保留一位小数，N=0 时 percent 为 null。discussion_pages 仅计已知平台/作品身份，不是独立用户数。报告可以采用更粗的显示精度，但不能改变快照中的 n/N。

## 验收

运行 `python scripts/validate_quantitative.py <run-dir> --output <run-dir>/quantitative-validation.json`。校验模式、必需表、问题连接、快照哈希、资格、逐轴归属覆盖、未知/多标签规则及每行成员和 n/N/比例/讨论页数。缺表、漏分类记录、重复来源、篡改成员或算错比例均应失败。

另外继续运行原有 analysis、opinions 和 coverage 校验，按 [coverage.md](coverage.md) 披露未处理与待核数量。定量脚本通过不能证明全量原文已读、分类语义正确、抽样具有代表性或页面已经展示正确数字。成稿需逐项核对“主问题要求的统计是否存在、口径是否可读、结论是否受数据支持”，并按 [output.md](output.md) 审阅统计、场景与解释是否共同回答问题；算术完成不能替代研究综合。
