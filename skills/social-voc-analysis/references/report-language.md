# 正式报告的语言与编辑审阅

用于本技能交付的标题、正文、图表、注释、来源说明、展开内容、页脚及导出。默认采用专业、客观、简洁、可独立阅读的书面语；不用抒情、煽情、拟人化、营销或聊天式表达包装研究结论。用户明确要求其他文体时调整，证据与归属规则不变。

## 准确命名与明确判断

已有准确的业务、场景或功能名称时直接使用。区分用户任务、产品功能与实现方式，不把一次场景描述自行对应到某项未确认的功能。标题应说明对象及发现或问题，避免用隐喻、情感叙事、抽象口号让读者猜测含义。

例如，“让记录成为生活的温柔陪伴”没有说明具体需求；材料确实支持时可写“自动记录减少重复录入”。“体验全面升级”需要改成有依据的具体变化，如“减少提交步骤”；没有比较数据时不能补写提升幅度。

区分功能评价、使用自述、已核实事实、研究推断与设计建议，并使证据强度进入句子；不必把这些类别机械做成每段的标签。情绪可以是有原声支持的研究对象，保留用户的担忧、满意或压力，不将其夸大成普遍心理，也不借研究者的抒情替代行为解释。

## 将分析记录写成报告

内部台账负责完整记录依据与判定，正文负责说明发现及其意义。保留证据关系，不照搬 `interpretation / limits / counter_ids / assessor` 等字段名、流程标签或“研究者归纳”前缀。

- 直接写清谁在何种情况下关注什么。概括段不必先宣布“研究者认为”或“分析显示”；需要与事实区分的推断，用“这些表达可能反映……”等有条件的语句，并说明依据。
- 不虚设真人研究员、专家、团队、机构或实地验证。模型完成的整理，在方法中准确说明；有真人参与时才按真实角色署名。“本报告”可用来说明范围，不为每个判断添一个作者角色。
- 统计、对照或归纳的主体是样本时，写“本次评论样本”“受访者自述”等真实对象，不扩大为“公众普遍”“车主都”“市场已经”。来源身份未知时使用“评论者”“帖子作者”。
- 判断尽量包含具体对象、行为或问题。遇到“问题层级差异”“信任摩擦”“沟通接受度”“机制”等抽象概念，先写出对应的实际表达；缺少具体材料时缩小判断，不能仅换成另一个术语。删去重复概括和无证据的拔高，保留支撑判断所必需的条件与因果解释。

## 让证据强度进入句子

| 表达任务 | 推荐写法 | 应避免的问题 |
|---|---|---|
| 转述机构说明 | “某机构在初步说明中称……” | 将一方声明改写为已证实事实，或含糊写成“官方已证实” |
| 归纳讨论 | “部分评论要求公开检测依据。” | “调查透明度存在系统性信任危机”，但材料仅有几条疑问 |
| 提出解释 | “对检测过程的疑问，可能与说明缺少具体依据有关。” | 直接断定动机、因果或组织行为 |
| 说明证据不足 | “现有材料不足以判断实际退订情况。” | 反复写“本研究未验证”“不能证明”，使限制取代正文 |
| 展示不同看法 | “也有评论主张等待调查结果。” | 机械称为“反证”；不同立场未必反驳当前事实主张 |

原声逐字保留，不能为了正式语气改掉作者原文。侮辱、讽刺和夸张表达按必要性选用，正文概括其含义并准确归属，不能借引文替报告下结论。引文来源与技术路径保留可查。

## 组织正文而不堆免责声明

每项发现先回答问题，再用最有解释力的材料支撑，必要时补充不同看法和影响判断的限制。无需为每项发现固定生成“观察—解释—边界—反例”四个标签，也不要求每段都出现不同看法。

直接影响本项判断的限制放在附近，例如“这里记录的是购买意向，尚无退订数据”；搜索抽样、作者身份未验证等共通限制集中放在样本与方法。集中说明不等于隐藏重要限制，也不允许把来源说法无归属地提升为事实。

制作过程、工具协议、哈希字段、校验通过数和未安装依赖等放在交付记录或方法详情。删除“没有把目标数写成完成数”“不为凑数追加”等自我评价，直接报告目标、实际取得量与不足原因。正文用“支持材料”“其他观点”“调查资料”这类具体入口，不默认显示随机短ID。

同一段观点概括与原文高度重复时，只保留有用的一层概括与一次原文展示。统计单位要准确，但优先使用“笔记”“评论及回复”等可理解的名称；专业定义在方法中一次说明。

## 两轮交付审阅

1. **证据与逻辑。** 检查每个标题、归纳和解释是否有对应材料；事实是谁说的；范围、时间和比较是否一致；不同观点是否被误当反证；限制是否改变结论。发现实质判断需要变化时修订分析版本，不能以润色名义静默更改编码。
2. **实际成稿。** 以首次阅读报告的业务读者身份通读标题、正文、图表、筛选标签、展开内容、页脚与导出。检查标题能否独立表达发现、功能和场景命名是否准确、每句是否说明具体问题、语气是否客观，是否存在抒情或口语化包装、重复概括及术语堆砌；同时核对身份、限制和原声归属。不要只读生成器或JSON字段。信息层级另按 output.md、HTML 界面另按 report-design.md 验收。

可使用 `scripts/review_report_language.py` 扫描常见候选问题；它略过逐字引文和原文区，并区分正文与方法。输出的是待审清单，不是语义判决。零命中不能替代上述两轮审阅，不得为消除提示而删掉有意义的限定或改动原声。

保留审阅结果、展示稿版本和源分析文件哈希。仅作语言修订时，维持统计值、引文、证据ID和采集时间，记录为“文字修订”，不宣称完成新采集或新分析。原始材料与既有分析快照继续保留。
