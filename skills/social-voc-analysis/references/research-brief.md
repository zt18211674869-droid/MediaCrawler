# 从用户意图设计研究

## 先解决会改变研究方向的缺口

利用已有对话与材料，判断报告帮助用户了解什么或作出什么决定。目的明确就沿用；“了解各家定位、优势、不足”足以开始竞品研究，不再让用户确认一遍。“竞品分析”若可能意味着了解格局、选择产品或寻找创业切入点，且上下文不能确定，先问能消除分歧的关键问题。

时间、地区、人群若会改变答案，也属于关键缺口。格式与配色等可逆细节通常自行决定。等待关键回答时可盘点材料和工具，不先代选目的批量采集；超时不等于接受假设。用户明确委托自行判断时，记录假设与依据。

## 检查分析方法能否达到目的

采集前在 research-spec 中明确主问题及下表关系，不预写结论，也不额外增加审批环节。按 [module-framework.md](module-framework.md) 选择核心与可选模块，记录模块对应的问题、证据门槛及指标口径；不以覆盖所有模块为完成目标。

| 设计项 | 应明确什么 |
|---|---|
| 子问题 | 哪些问题回答后，用户就能理解或判断；每个问题分配稳定 ID |
| 比较范围 | 产品身份、相关任务、人群、时间；替代方案与直接竞品是否需要分别比较 |
| 所需证据 | 产品定位、实际操作、自述体验、期待与宣传各能支持什么 |
| 分析方法 | 同维度比较、方面级正负向、观点聚类、场景/旅程或心理模型，为什么适用 |
| 完成标准 | 要说清什么差异、条件和边界；证据不足时能交付到哪里 |
| 关键缺口 | 哪些缺口会改变结论；需要补采、实测、访谈，还是明确保留未知 |

竞品研究不只列功能：定位看产品方与使用任务；优势看具体正向经验；不足看障碍、后果和补救；评价分歧结合场景与阶段解释。研究机制同样服务“了解竞品”，不自动扩展为MVP或设计方案。

对象可从小批材料中发现。同名应用先消歧；产品、合集、原型和纸本不能直接作为同层产品打分。用户指定的对象必须覆盖，即使只能写未知。某个维度只有产品宣传时，不能据此填出用户满意度。

## 按证据缺口取样与停止

每个检索/详情/评论任务都对应研究问题。数量目标与问题覆盖分别记录：用户指定100篇，应完成所要求的相关样本研究，但不等于展示100篇摘要，也不意味着竞品证据已经均衡。

在已授权预算内，优先补会改变判断的缺口，如主要竞品只有宣传、同一评价存在未解释矛盾、关键步骤没有上下文。不以追求完整为由无限追加；受预算、服务或材料可得性限制时，明确缩小结论范围。

在 evidence_gaps 中按问题、对象和材料性质记录缺口、补采任务与停止理由；主计划、问题回答状态及历史兼容见 [运行规范](run-workflow.md)。只在本 Skill 的 guaikei MCP 或已有本地材料范围内执行取证；实测和访谈可作为后续建议，不在本流程自动调用外部服务。

## 安排阅读层次

根据真实发现确定核心回答。总览便于快速了解；主体深度由问题、证据与用户要求决定，不设整篇固定字数。比较、观点分类、关键词/词云、场景旅程、心理模型是可组合的分析视角，选择能增加解释的内容；用户指定的模块应回应，资料不足则说明具体缺口。时间趋势、传播和行动方案仅在问题需要且证据满足条件时加入。

方法详表、原文与逐行编码保留查询入口；会改变判断的限制跟随相关结论，不藏到附录。详见 [output.md](output.md)。

## 连续研究与长期记录

把三类内容分开维护：

- **稳定方法与已明确偏好**：保留在 Skill 或项目已有规则中，例如意图优先、证据可追溯、分层阅读。不要把某轮主题、固定产品数或旧结论固化为通用模板。
- **本轮研究设置**：在 research-spec 保存用户目的依据、问题—证据—方法关系、范围和完成标准。新指令改变目的时记录变化，不覆盖旧轮研究设置。
- **有时间的历史发现**：保留来源快照、采集日、分析日、产品事实核验日和基准 run。引用旧结论须核对时效与口径，不把再分析日期冒充重新采集日期。

复用旧材料时，先说明继承什么、重审什么。新观点层可单独建立，原始材料与历史编码保持可追溯；记忆帮助延续研究，不能代替本轮取证。
